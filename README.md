# WERA

GitHub Pages에서 동작하는 텍스트 게임 구동기입니다. C# / Blazor WebAssembly로 만듭니다.

## 사용법
1. 페이지에 게임팩(`.wra`)을 드래그 드롭합니다.
2. 새 게임을 시작하거나, 세이브(`.wsv`, 내용은 JSON)를 드래그 드롭합니다.

## 게임팩 형식 (잠정)
TSV 파일 묶음(zip 형식)이고 확장자는 **`.wra`**입니다(zip 압축 파일의 이름을 `.wra`로 바꾼 것과 같습니다). 첫 줄은 헤더입니다.

**값의 타입:** 모든 코드(던전, 상점, 아이템, 캐릭터, 교환, 플래그 코드 등), 수량(어마운트, 소지제한), 캐릭터 수치(레벨, HP, XP 등), 플래그 값은 `long` 정수입니다. 그룹넘버(`group_number`)만 `int`입니다. 코드를 숫자가 아닌 이름으로 쓸 수 없습니다(예: 플래그 코드 `1001`). 게임팩 `id`는 문자열입니다.

**스킬 마스터**(모두 선택, 아직 전투에는 쓰이지 않음): `skill_slot_master`(`code`, `name`; `code`가 키), `character_skill_slot_tag_master`(`character_code`, `skill_slot_code`, `group_number`(정수), `tag_code`, `is_positive`; 앞의 네 열이 키, 캐릭터는 캐릭터 인벤토리, 스킬 슬롯은 스킬 슬롯 마스터, 태그는 태그 마스터에 있어야 함), `skill_master`(`code`, `name`; `code`가 키), `skill_tag_master`(`skill_code`, `tag_code`; 두 열이 키), `skill_execute_effect_master`(`skill_code`, `execute_number`, `effect_type`, `value_1`, `value_2`, `value_3`; 앞의 두 열이 키, 값은 비우면 0)입니다. `effect_type`은 `EffectType` 이름(대소문자 무시, 숫자는 안 됨)으로 적습니다. 마스터만으로는 스킬의 동작을 정할 수 없어서 이펙트 종류마다 동작을 코드로 구현하고 마스터는 어느 종류를 어떤 값으로 쓸지만 적으며, 지금 있는 종류는 `None`(아무 일도 안 함), `CacheToTargetModValue`(서킷 캐시의 `value_2`번 값을 타겟의 `value_1`번 스테이터스에 더함), `CacheToTargetSetValue`(그 값으로 바꿈), `CacheToCasterModValue`/`CacheToCasterSetValue`(같은 일을 시전자에게), `CasterValueToCache`/`TargetValueToCache`(시전자나 타겟의 `value_1`번 스테이터스 값을 캐시의 `value_2`번에 씀; 캐시가 짧으면 모자란 칸을 0으로 채우고, 그 스테이터스가 없으면 캐시를 건드리지 않음)입니다. 스테이터스를 다루는 종류(위의 여섯 개)는 `value_1`이 스테이터스 마스터의 `status_code`, `value_2`가 0~255(`GamePack.MaxCacheIndex`)의 `cache_index`여야 하고(아니면 로드 오류) `value_3`은 보지 않습니다. **캐시 계산**(`CacheAdd`, `CacheSubtract`, `CacheMultiply`, `CacheDivide`)은 `cache[value_1] = cache[value_2] (연산) cache[value_3]`이고 세 값 모두 0~255의 `cache_index`입니다(결과 칸이 캐시보다 뒤면 0으로 채워 늘림; 나눗셈은 decimal 그대로 반올림 없음; 계산할 칸이 없거나 0으로 나누거나 decimal 범위를 넘으면 아무 일도 하지 않음). **`SetCacheValue`**는 캐시에 상수를 씁니다: `cache[value_1] = value_2 / 10^value_3`(`value_3`은 소수 자릿수 0~28; 15, 2는 0.15). **분기**는 이벤트/ADV 흐름과 같은 방식입니다: `Jump`(`value_1`이 점프할 `execute_number`), `JumpCacheEqual`/`NotEqual`/`GreaterThan`/`GreaterOrEqual`/`LessThan`/`LessOrEqual`(`cache[value_1]`과 `cache[value_2]`를 견주어 참이면 `value_3`의 `execute_number`로 점프, 거짓이거나 칸이 없으면 다음 이펙트로), `Finish`(거기서 실행을 끝냄). 점프 대상은 같은 스킬에 있고 자신의 `execute_number`보다 커야 합니다(뒤로만 가서 무한 반복이 없고, 아니면 로드 오류). 번호 사이가 비어 있어도 됩니다. 이펙트는 **스킬 서킷**(`SkillExecuteCircuit`)에서 실행됩니다: 시전자와 타겟(`BattleUnit`)을 등록한 서킷이 스킬의 이펙트를 실행 번호 순서로 실행하고, 이펙트끼리는 서킷의 `CacheValues`(`List<decimal>`)로 값을 주고받습니다. `BattleUnit`은 캐릭터 스테이터스 마스터의 행으로 스테이터스 값(decimal)을 채우고, 값을 바꾸면 그 스테이터스의 최솟값~최댓값으로 맞춥니다. 타겟에게 그 스테이터스가 없거나 캐시에 그 번호의 값이 없으면 이펙트는 아무 일도 하지 않습니다. 전투의 실행 버튼에는 아직 연결되어 있지 않습니다. 보조키는 캐릭터 코드, (캐릭터, 스킬 슬롯, 그룹), 스킬 코드(스킬 태그와 스킬 이펙트 둘 다)입니다. 조회는 `GamePack.FindSkillSlot`, `FindSkill`, `SkillSlotTagsOf(캐릭터)`/`SkillSlotTagsOf(캐릭터, 스킬 슬롯, 그룹)`, `TagsOfSkill`, `SkillExecuteEffectsOf`(실행 번호 순)입니다.

**스킬 순서 이펙트**(`skill_order_effect_master`, 선택): 스킬을 쓰는 순서를 정하는 OrderPoint를 계산합니다. 열과 키는 `skill_execute_effect_master`와 같고(`skill_code`, `execute_number`, `effect_type`, `value_1`~`value_3`; 앞의 두 열이 키, 보조키 `skill_code`) 종류는 따로의 `OrderEffectType`입니다: `None`, `CasterValueToCache`, `TargetValueToCache`, `SetCacheValue`, `CacheAdd`/`Subtract`/`Multiply`/`Divide`, `Jump`, `Finish`, `JumpCache*`(여섯 가지 비교), 그리고 `CacheToResult`(`Result = cache[value_1]`). 인자 규칙은 실행 이펙트의 같은 이름과 같습니다. 유닛의 스테이터스를 바꾸는 종류(`CacheToTarget*`, `CacheToCaster*`)는 없어서 순서 계산은 스테이터스를 읽기만 합니다. **순서 서킷**(`SkillOrderCircuit`)은 시전자와 타겟, 캐시, `Result`를 갖고 순서 이펙트를 실행 번호 순서로 실행하며, 실행이 끝난 뒤의 `Result`가 OrderPoint입니다(`CacheToResult`가 바꾸지 않으면 0). 조회는 `GamePack.SkillOrderEffectsOf`입니다. 실행 이펙트 마스터의 이름은 예전에 `skill_effect_master`였고 `skill_execute_effect_master`로 바뀌었습니다(게임팩 파일 이름과 `SkillExecuteEffect*` 이름도 같이). **행동 순서**(`ActionOrder.Sort`): OrderPoint가 큰 쪽이 먼저 행동합니다. 같은 값일 때의 처리는 TODO이고 지금은 적군이 먼저, 같은 진영이면 슬롯 번호(전위 왼쪽이 0)가 작은 쪽이 먼저입니다. 아직 전투에 연결되지 않았습니다.
**스킬 슬롯 규칙**: `character_skill_slot_tag_master`는 장비 슬롯 태그와 같은 규칙입니다. 같은 (캐릭터, 스킬 슬롯)에서 같은 `group_number`인 행들이 한 그룹이고, 그룹 안은 모두 만족해야 하며(AND; `is_positive`가 참이면 스킬이 그 태그를 가져야 하고 거짓이면 가지면 안 됨) 그룹끼리는 OR입니다. 규칙이 하나도 없는 슬롯에는 아무 스킬도 넣을 수 없습니다. 판정에는 캐릭터의 마스터 태그와 스킬의 태그를 합쳐서 봅니다: `GamePack.CanSlotSkill(캐릭터, 슬롯, 스킬)`, `SlottableSkills(캐릭터, 슬롯)`, `SkillFits(캐릭터, 슬롯, 태그들)`. 스킬 실행 서킷의 이름은 `SkillExecuteCircuit`입니다(예전 `SkillCircuit`).

**이벤트, ADV, 전투 마스터**(모두 선택, 아직 게임 진행에는 쓰이지 않음): `event_master`와 `adv_master`, `battle_master`는 `code`(키), `name`입니다. `event_condition_master`는 던전/상점과 같은 조건표 규칙(그룹 안 AND, 그룹끼리 OR, `condition_type`은 `None` 등, 복합키 `(event_code, group_number, flag_code)`)이고 조건이 없는 이벤트는 늘 열립니다. `event_flow_master`의 키는 `(event_code, flow_number)`이고 `flow_type`(이름으로 적음)과 정수 `param_1`~`param_3`(비우면 0)가 값입니다. 종류와 번호는 `None`=0, `Finish`=1(이벤트 끝), `Jump`=2(조건 없이 점프: `param_1`이 점프할 같은 이벤트의 `flow_number`이고 **자신의 `flow_number`보다 커야 합니다** — 뒤로만 점프하므로 무한 반복이 생기지 않습니다), `Adv`=3(`param_1`이 재생할 `adv_master`의 코드), `Battle`=4(`param_1`이 개시할 `battle_master`의 코드), `SetFlag`=5(`param_1`이 플래그 코드, `param_2`가 값: 플레이어 플래그를 그 값으로 바꿈), `ModFlag`=6(같은 인자: 플래그에 값을 더함, 음수면 뺌, 없던 플래그는 0에서 시작, long 범위 끝에서 멈춤), `AddInventory`=7(`param_1`이 인벤토리 코드, `param_2`가 개수 — 아래 **AddInventory** 참고), `JumpFlagEqual`=8, `JumpFlagNotEqual`=9, `JumpFlagGreaterThan`=10, `JumpFlagGreaterOrEqual`=11, `JumpFlagLessThan`=12, `JumpFlagLessOrEqual`=13(아래 **JumpFlag\*** 참고), `JumpInventoryEqual`=14, `JumpInventoryNotEqual`=15, `JumpInventoryGreaterThan`=16, `JumpInventoryGreaterOrEqual`=17, `JumpInventoryLessThan`=18, `JumpInventoryLessOrEqual`=19(아래 **JumpInventory\*** 참고), `JumpCharacterHaveTag`=20, `JumpUniqueItemHaveTag`=21(아래 **태그 점프** 참고), `JumpRandom`=22(아래 **JumpRandom** 참고)이고, `SetFlag`, `ModFlag`, `AddInventory`는 **화면에 나오지 않는 칸**이라 멈추지 않고 바로 다음 칸으로 갑니다(바뀐 플래그는 뒤의 칸 조건에 바로 보이고 세이브에 담김). `param_3`은 지금은 쓰이지 않고(앞으로를 위해 남김) `param_2`는 `SetFlag`/`ModFlag` 외에는 쓰이지 않습니다. Jump의 `param_1`, `JumpFlag*`의 `param_3`, Adv, Battle의 `param_1`은 로드할 때 검증합니다(Adv와 Battle은 그 마스터가 있어야 함). **흐름 조건 마스터(`event_flow_condition_master`, `adv_flow_condition_master`)는 없어졌습니다.** 이 파일이 게임팩에 있으면 "더 이상 쓰이지 않습니다" 오류로 로드가 실패합니다. 조건에 따라 칸을 건너뛰려면 `JumpFlag*`로 뛰어넘고, ADV에서 선택지를 숨기려면 `JumpFlag*`로 선택지가 다른 **다른 선택지 묶음**으로 뜁니다. 이벤트는 이벤트 마스터에 있어야 하고 같은 키를 두 번 쓸 수 없습니다.

**ADV 흐름 마스터**: 키는 `(adv_code, flow_number)`이고 `flow_type`은 이름으로 적습니다(`AdvFlowType`: `None`=0, `Finish`=1, `Jump`=2, `TextMe`=3, `Choice`=4, `TextYou`=5, `TextPlain`=6, `SetFlag`=7, `ModFlag`=8, `AddInventory`=9, `JumpFlagEqual`=10, `JumpFlagNotEqual`=11, `JumpFlagGreaterThan`=12, `JumpFlagGreaterOrEqual`=13, `JumpFlagLessThan`=14, `JumpFlagLessOrEqual`=15, `JumpInventoryEqual`=16, `JumpInventoryNotEqual`=17, `JumpInventoryGreaterThan`=18, `JumpInventoryGreaterOrEqual`=19, `JumpInventoryLessThan`=20, `JumpInventoryLessOrEqual`=21, `JumpCharacterHaveTag`=22, `JumpUniqueItemHaveTag`=23, `JumpRandom`=24, `TextLog`=25). `Jump`는 조건 없이 점프하며 `param_1`이 점프할 같은 ADV의 `flow_number`로 자신보다 커야 합니다(뒤로만 점프). `Choice`는 한 행이 선택지 하나이고(조건이 없어 묶음의 모든 행이 늘 나오며, 일부를 숨기려면 `JumpFlag*`로 다른 묶음으로 뜁니다) `param_1`이 선택지 그룹 아이디, `param_2`가 그 선택지를 고르면 점프할 같은 ADV의 `flow_number`이며 이것도 자신보다 커야 합니다. 같은 ADV에서 `param_1`(선택지 그룹)이 같은 `Choice` 행들은 `flow_number` 순으로 연속해야 하고(다른 칸이 끼어들 수 없음) 그룹 아이디는 ADV마다 따로입니다. `SetFlag`(`param_1`이 플래그 코드, `param_2`가 값: 플레이어 플래그를 그 값으로 바꿈)와 `ModFlag`(같은 인자: 플래그에 값을 더함, 음수면 뺌, 없던 플래그는 0에서 시작, long 범위 끝에서 멈춤)는 **화면에 나오지 않는 칸**이라 멈추지 않고 바로 다음 칸으로 가며 대사 로그에도 남지 않고, 바뀐 플래그는 뒤의 칸 조건에 바로 보이고 세이브에 담깁니다(`text`는 비워 둡니다). `TextMe`(나의 대사), `TextYou`(상대의 대사), `TextPlain`(화자 없는 일반 텍스트)은 `text` 열의 문장을 보여 주며 `text`가 비어 있으면 안 되고 인자는 아직 쓰이지 않습니다. `TextMe`와 `TextYou`는 같은 규칙으로 화자를 정합니다: `param_1`은 말하는 캐릭터 코드, `param_2`는 그 캐릭터 이미지의 `variation_number`이며, `param_1`이 0이거나 없는 캐릭터면 이름은 `???`, 이미지는 No Image입니다(오류가 아닙니다). **JumpFlag\***(`JumpFlagEqual`, `JumpFlagNotEqual`, `JumpFlagGreaterThan`, `JumpFlagGreaterOrEqual`, `JumpFlagLessThan`, `JumpFlagLessOrEqual`; 이벤트와 ADV 공통): `param_1`이 `flag_code`, `param_2`가 `flag_value`, `param_3`이 `target_flow_number`입니다. 플레이어 플래그(없으면 0)를 `flag_value`와 견주어 참이면 `target_flow_number`로 점프하고 거짓이면 다음 칸으로 갑니다. 점프할 번호는 **같은 이벤트/ADV에 있는 자신보다 큰 흐름 번호**여야 해서(로드 검증) 뒤로만 가고 무한 반복이 생기지 않습니다. 조건 없이 점프하려면 `Jump`를 씁니다. **JumpInventory\***(`JumpInventoryEqual`, `JumpInventoryNotEqual`, `JumpInventoryGreaterThan`, `JumpInventoryGreaterOrEqual`, `JumpInventoryLessThan`, `JumpInventoryLessOrEqual`; 이벤트와 ADV 공통): `JumpFlag*`와 같은 모양으로 `param_1`이 `inventory_code`, `param_2`가 `value`(개수), `param_3`이 `target_flow_number`입니다. 플레이어가 가진 그 인벤토리 코드의 개수를 `value`와 견주어 참이면 점프하고 거짓이면 다음 칸으로 갑니다. 개수는 커먼 아이템은 보유 개수, 번치 아이템은 부품이 모두 갖춰진 세트 수(부품별 보유 개수 ÷ 부품 어마운트의 최솟값), 유니크 아이템은 그 코드의 인스턴스 수, 캐릭터는 보유하면 1 아니면 0이고 없으면 0입니다. `inventory_code`는 인벤토리 마스터에 있어야 하고 점프할 번호는 `JumpFlag*`와 같이 같은 이벤트/ADV의 자신보다 큰 흐름 번호여야 합니다(로드 검증). 같은 이벤트/ADV 안에서 `AddInventory`로 바뀐 인벤토리가 바로 반영됩니다. **태그 점프**(`JumpCharacterHaveTag`, `JumpUniqueItemHaveTag`; 같은 인자와 규칙): `param_1`이 확률, `param_2`가 모수, `param_3`이 `target_flow_number`입니다. 0 이상 모수 미만의 무작위 정수 `r`을 뽑아 `r < 확률`이면 점프하고 아니면 다음 칸으로 갑니다(예: `30, 100, 5`는 `rand(100) < 30`이면 5번 칸으로, 아니면 다음 칸으로. `rand(100)`은 0..99). 확률이 0 이하면 절대 점프하지 않고 모수 이상이면 늘 점프합니다. 모수는 1 이상이어야 하고(로드 검증) 점프할 번호는 다른 점프와 같이 같은 이벤트/ADV의 자신보다 큰 흐름 번호여야 합니다. 난수는 `GameSession.NextRandom`(기본 `Random.Shared`, 저장되지 않으며 시험이나 연출을 위해 바꿔 끼울 수 있음)이 만듭니다. **AddInventory**(이벤트 흐름 7, ADV 흐름 9; 같은 인자와 규칙): `param_1`이 인벤토리 코드(커먼, 번치, 유니크 아이템, 캐릭터가 함께 쓰는 코드 공간), `param_2`가 개수이고 음수면 뺍니다. 화면에 나오지 않는 칸이라 실패해도 알리지 않고 가능한 만큼만 합니다. 커먼 아이템은 소지 한도에서 멈추고 뺄 때는 장비 슬롯에 끼지 않은 보유량에서 멈추며 0개가 되면 보유 목록에서 빠집니다. 번치는 부품으로 풀어 같은 방식으로 처리합니다. **유니크 아이템과 캐릭터는 개수가 `1` 또는 `-1`이어야 하고(로드 검증)**, `1`은 유니크 아이템 인스턴스를 새로 얻거나 캐릭터를 얻고(이미 보유하면 아무 일 없음), `-1`은 장비에 끼지 않은 인스턴스 하나(작은 ID부터)를 내거나 보유 캐릭터를 내보냅니다(없으면 아무 일 없음, 다른 캐릭터에게 장비로 끼워진 캐릭터는 못 내보냄). 인벤토리 코드가 마스터에 없으면 로드 오류이고, 플레이어 캐릭터(1)를 `-1`로 내보내는 것도 로드 오류입니다. **대사 꾸밈(BBCode)**: `text`에는 `
`(줄바꿈), `[b]…[/b]`(굵게), `[color=이름]…[/color]`(글자색: red, orange, yellow, green, cyan, blue, purple, pink, white, gray 또는 `#rgb`/`#rrggbb`)를 쓸 수 있고, 글자 `[`, `]`, `\`는 `\[`, `\]`, `\`로 적습니다. 모르는 태그, 닫히지 않거나 짝이 맞지 않는 태그, 이스케이프 없는 `[`는 게임팩 로드 오류입니다. 화면에는 허용한 태그만 HTML로 바뀌어 나갑니다. **대사 상자 검증**: 화면 너비가 960px로 고정이라(뷰포트도 `width=960`) 상자 안에 한 줄 **83칸**(영문 1칸, 한글 등 전각 2칸, 태그는 칸을 차지하지 않음)이 들어가고, 어느 글자에서나 줄을 바꾸는 규칙으로 센 줄 수가 **3줄**(이름 자리를 뺀 상자 높이)을 넘으면 `TextMe`/`TextYou`는 로드 오류입니다. `TextPlain`은 아이콘 자리를 포함한 가로 전체에 아이콘과 같은 높이로 그리는 상자(이름 자리 없음)라 한 줄 **94칸**(`AdvLayout.PlainBoxColumns`) × 3줄 안에 들어가야 하고, `TextLog`는 상자 없이 글만 나와 문법만 봅니다. 상자 크기 상수는 `AdvLayout`에 있고 CSS와 같아야 합니다. `force_name`은 화자 이름을 강제하는 특별 연출용 열로(`TextMe`와 `TextYou`), 비어 있으면 캐릭터 이름을 씁니다. `Choice`의 `text`는 선택지 문구로 쓸 수 있고, 그 외 종류는 비워 둡니다. ADV 재생에 쓰입니다.

**memo 열:** 모든 마스터 TSV는 헤더에 `memo` 열을 둘 수 있고(위치 자유) 사람이 보는 메모일 뿐이라 엔진은 읽지 않으며 마스터메모리에도 올리지 않습니다. 기본 게임팩은 엔진이 요구하는 필수 행(예약 태그와 스테이터스, 플레이어 캐릭터와 그 속성/태그, 모든 캐릭터의 level/hp 레벨 0 행)의 메모에 "필수"라고 적어 두었고, 테스트용 던전(`1999`)과 상점(`2999`, 커먼/유니크/캐릭터 교환 포함)은 필수가 아니며 조건이 없어 새 게임부터 열려 있습니다.

**필수 마스터 방침:** 엔진이 검증하는 마스터(예약 코드나 필수 항목이 있는 마스터)는 로드할 때 존재부터 확인합니다. 없으면 "`...`가 반드시 필요합니다" 오류로 로드되지 않습니다. 필수 마스터는 `attribute_master`, `tag_master`(예약 태그 1 플레이어, 2 리더), `status_master`(예약 스테이터스 1 level, 2 hp), `character_inventory_master`(캐릭터 1 = 플레이어), `character_tag_master`(캐릭터 1의 플레이어 태그), `character_status_master`(모든 캐릭터의 level/hp 레벨 0 행), `time_slot_master`와 `turn_master`(시간대 FK, 시작 턴 한 행 이상), `common_item_inventory_master`와 `common_item_tag_master`(메인 통화)입니다. 나머지는 선택이고, 선택 마스터가 있으면 가리키는 상위 마스터도 있어야 합니다.

### 아이템과 상점 교환
- **커먼 아이템 인벤토리**(`common_item_inventory_master`)는 아이템 코드, 이름, 소지제한(`carry_limit`, 한 번에 소지할 수 있는 최대 수량, 1 이상의 정수)입니다.
- **번치 인벤토리**(`bunch_item_inventory_master`)는 여러 아이템을 묶은 것으로, 같은 `inventory_code`의 행들이 하나의 번치가 됩니다(행마다 `item_name`은 같아야 함). `part_item_code`는 아이템 인벤토리의 아이템만 가리킬 수 있고, 번치에는 소지제한이 없으며, `part_amount`는 1 이상입니다.
- **인벤토리 코드는 하나의 코드 공간**입니다: 커먼 아이템, 유니크 아이템, 번치 아이템, 캐릭터 인벤토리 마스터의 코드 열은 모두 `inventory_code`이고, 게임팩을 읽을 때 네 마스터를 `inventory_code`로 찾는 하나의 사전(`GamePack.Inventory`: 코드 → 종류와 이름)으로 합칩니다. **같은 코드가 두 마스터에 있으면(같은 마스터 안에서도) 읽지 못합니다.** 캐릭터 1은 플레이어이므로 아이템은 1번을 쓸 수 없습니다. **커먼 아이템 2는 메인 통화**입니다(기본 게임팩에서는 "금화", 이름은 게임팩 마음대로): 커먼 아이템 인벤토리에 반드시 있어야 하고 `common_item_tag_master`에서 **메인 통화 태그(3)를 반드시 가집니다.** 메인 통화 태그는 아이템 2만 가질 수 있어(다른 커먼 아이템, 유니크 아이템, 캐릭터가 가지면 로드 오류, 게임 중에도 더할 수 없고 세이브도 거부) 메인 통화는 둘 이상일 수 없습니다.
- 인벤토리 계통은 **커먼 아이템 / 유니크 아이템 / 번치 아이템 / 캐릭터** 네 종류입니다(`common_item_inventory_master`, `unique_item_inventory_master`, `bunch_item_inventory_master`, `character_inventory_master`).
- **캐릭터 인벤토리**(`character_inventory_master`)는 열이 `inventory_code`, `character_name`, `carry_limit`, `advantage_attribute_code`, `disadvantage_attribute_code`인 마스터입니다. 모든 캐릭터는 **유리속성**과 **불리속성**을 하나씩 가져야 하고, 둘 다 속성 마스터에 있어야 하며 서로 달라야 합니다.
- **스테이터스**(`status_master`)는 스테이터스의 종류(level, hp, xp, exp 등)이고, **캐릭터 스테이터스**(`character_status_master`)는 캐릭터 × 스테이터스 × 레벨별 값입니다. 복합키는 `(character_code, status_code, level)`이고 값은 `initial_value`, `min_value`, `max_value`(모두 정수)입니다. `min_value <= initial_value <= max_value`여야 하고, `level`은 0 이상입니다. **폴백**: 현재 레벨의 행을 먼저 찾고, 없으면 `level` 0의 행을 씁니다. 캐릭터를 만들 때는 레벨이 정해지지 않았으므로 `level` 0의 행을 읽습니다. 엔진이 예약한 스테이터스 코드는 **1 = level, 2 = hp, 3 = xp**입니다(이름은 자유). `status_master`에는 **level(1)과 hp(2)가 반드시** 있어야 하고, `character_status_master`에는 **모든 캐릭터에게 level과 hp의 `level` 0 행이 있어야** 합니다(어기면 로드 오류). xp(3)는 선택입니다. 캐릭터를 새로 얻을 때(`AddCharacter`) 상태가 레벨 0 행으로 채워집니다: 레벨 = level의 `initial_value`, HP = hp의 `initial_value`(최대 HP는 `max_value`), 경험치 = xp의 `initial_value`(필요 경험치는 `max_value`). **xp 행이 없으면 0/0**으로 시작합니다.
- **속성**(`attribute_master`)은 속성 코드와 이름입니다. 속성 아이콘 이미지는 아직 경로 규칙이 없어 `No Image`로 표시합니다.
- **상태이상**(`status_effect_master`)은 상태이상 코드와 이름입니다. 캐릭터에 걸려 있는 상태이상은 세이브에 저장하며(아래 "상태이상 저장"), 파티 설정 슬롯의 아이콘 줄에 아이콘으로 나옵니다.
- **임베디드 이펙트**는 TSV로 정의하는 마스터가 아니라 **구동기에 하드코딩된 클래스**입니다. `EmbeddedEffect`(추상 클래스)를 상속해서 만들고 `EmbeddedEffectRegistry.Default`(등록부)에 등록합니다.
  - **생성자**가 `(Character target, long value1, long value2, long value3)`를 받아 `Target`, `Value1~3`에 **저장**합니다.
  - `abstract long EffectCode`: 이펙트 코드.
  - `abstract void Execute()`: **파라미터 없이**, 저장해 둔 타겟과 밸류로 실행만 합니다.
  - 등록부에는 인스턴스가 아니라 `(이펙트 코드, 만드는 방법)`을 등록합니다. 예: `new(1, (t, a, b, c) => new HealEffect(t, a, b, c))`. `Create(코드, 타겟, 밸류 1~3)`로 이펙트를 만들면(실행하지 않음) 그 이펙트의 `Execute()`를 부릅니다. 만들어진 이펙트의 `EffectCode`가 등록한 코드와 다르면 오류입니다.
  - `Character`는 마스터 정의(`Entry`)와 바꿀 수 있는 현재 상태(`State`)를 함께 가집니다.
  - **내부 카운터와 유효 플래그:** 이펙트는 `Counter`(처음 0)와 `IsValid`(처음 true)를 가집니다. 이 둘은 익스큐터(`EffectExecutor`)만 바꿉니다.
  - **익스큐터:** `Run()`은 유효한 이펙트를 추가한 순서대로 한 번씩 `Execute()`하고, 실행할 때마다 카운터를 1 올립니다. 카운터가 **`Value2` 이상**이 되면 그 이펙트는 무효(`IsValid = false`)가 되어 다음 `Run()`부터 돌지 않고, 실행이 끝날 때 목록에서 폐기됩니다. 즉 **`Value2`는 최대 실행 횟수**입니다(0 이하여도 한 번은 실행됨). `Execute()`를 직접 부르면 카운터는 올라가지 않습니다.
  - **정의된 이펙트:**
    - `1` `HealEffect`: 타겟의 HP를 `Value1`만큼 늘립니다(음수면 줄임). HP는 0~최대 HP 안에 머뭅니다. `Value2`는 최대 실행 횟수, `Value3`은 쓰지 않습니다. 실행할 때 타겟이 이미 사망(HP 0 이하)했으면 HP를 바꾸지 않고 **조기 리턴**하며 이 이펙트를 **바로 무효**로 만듭니다(되살리지 않음). 이 이펙트의 실행으로 타겟이 죽은 경우에는 그 실행은 그대로 끝나고, 다음 실행 때 무효가 됩니다. 실행 횟수에 무제한은 없습니다(`Value2`가 0 이하여도 한 번만 실행).
- **상태이상 이펙트**(`status_effect_effect_master`)는 "상태이상(`status_effect_code`)이 `trigger_type` 시점에 임베디드 이펙트(`effect_code`)를 `effect_value_1~3`으로 실행한다"를 적습니다. 상태이상 코드는 상태이상 마스터에, 이펙트 코드는 임베디드 이펙트에 등록되어 있어야 하고 밸류는 비워 두면 0입니다. `priority`는 `long` 값이며 정렬 방향은 사용하는 쪽이 정합니다. `trigger_type`은 이름으로 적습니다(대소문자 무시, 숫자 불가).
  - `None`(조건 없음/시점 없음), `BeforeAttack`(공격하기 전), `AfterAttack`(공격한 후), `BeforeAttacked`(공격을 받기 전), `AfterAttacked`(공격을 받은 후), `AfterTurnStart`(턴 개시 후), `AfterTurnEnd`(턴 종료 후), `AfterBattleStart`(배틀 개시 후), `AfterBattleEnd`(배틀 종료 후), `AfterMove`(이동 후)
- `GameSession.ApplyEffect(이펙트 코드, 캐릭터 코드, 밸류 1~3)`은 이펙트를 만들어(타겟과 밸류 저장) `Execute()`로 보유 캐릭터에게 실행하고, 바뀐 상태를 세이브가 받아들이는 범위(레벨 1 이상, HP 0~최대 HP, XP 0~필요 XP)로 보정해 저장합니다.
- **장비**는 슬롯과 태그로 정합니다.
  - `equipment_slot_master`는 장비 슬롯의 종류(무기, 방어구 등), `tag_master`는 태그(검, 갑옷, 중량 등; **1 = 플레이어, 2 = 리더, 3 = 메인 통화는 엔진이 예약한 코드**라 반드시 이 번호로 있어야 하고 없으면 로드 오류입니다, 이름은 자유), `unique_item_inventory_master`는 유니크 아이템(`inventory_code`, `item_name`)입니다. **캐릭터 1은 플레이어**입니다: 캐릭터 1이 반드시 있어야 하고(이름은 게임팩 마음대로, 기본 게임팩에서는 "당신") `character_tag_master`에서 플레이어 태그(1)를 가져야 하며, **플레이어 태그는 캐릭터 1만** 가질 수 있습니다(다른 캐릭터나 아이템이 가지면 로드 오류, 게임 중에도 더하거나 뺄 수 없고 세이브도 거부). 플레이어는 상점 교환의 코스트로 낼 수 없고 내보낼 수 없습니다.
  - `unique_item_tag_master`, `common_item_tag_master`, `character_tag_master`는 각각 유니크 아이템, 커먼 아이템(아이템 인벤토리), 캐릭터가 가진 태그입니다(대상과 태그가 각자의 마스터에 있어야 하고, 같은 `(대상 코드, tag_code)`를 두 번 쓸 수 없음). **장비 슬롯에는 이 세 종류가 모두 들어갈 수 있습니다**(예: 강령술사가 강시 캐릭터를 장비). 어느 종류가 들어가는지는 슬롯 태그 규칙에 그 종류의 태그를 쓰는 것으로 정합니다. **장비 가능 판정은 (장비하는 캐릭터의 태그 + 끼울 것의 태그)를 합친 태그 집합으로 슬롯 태그 규칙을 검사합니다**(캐릭터 태그는 `character_tag_master`).
  - `equipment_slot_tag_master`는 **캐릭터의 장비 슬롯에 어떤 장비가 들어가는가**를 태그로 적습니다. **복합키는 앞의 네 열**(`character_code`, `equipment_slot_code`, `tag_code`, `group_number`)이고 `is_positive`는 값입니다. 같은 키를 두 번 쓰면 `is_positive`가 달라도 오류입니다. `is_positive`는 `true`/`false`(대소문자 무시) 또는 `1`/`0`입니다.
  - **부합 규칙**: 같은 (캐릭터, 슬롯)에서 같은 `group_number`가 한 그룹이고 **그룹 안은 모두 만족(AND), 그룹끼리는 하나만 만족해도 됨(OR)**입니다. `is_positive`가 참이면 장비가 그 태그를 **가져야** 하고, 거짓이면 **가지면 안 됩니다**. 규칙이 없으면 아무것도 낄 수 없습니다.
  - **캐릭터가 가진 장비 슬롯**은 이 마스터에 그 캐릭터로 나오는 슬롯입니다(처음 나온 순서). 행이 없는 캐릭터는 장비 슬롯이 없습니다.
  - **장비는 보유해야 낄 수 있습니다.** 유니크 아이템은 **한 개가 인스턴스 하나**입니다. 세이브의 `UniqueItems`(인스턴스 ID → `{InstanceId, ItemCode, OrderNumber, Tags}`(구조체 `UniqueItemInstance`; 인스턴스 ID와 마스터 코드를 함께 가지며 `InstanceId`가 없는 예전 세이브는 키로 채우고 `OrderNumber`가 없으면 0; `OrderNumber`는 얻을 때 소지 유니크 아이템 수(0부터)이고 목록의 순서이며 순서를 바꿀 때 조작), **인스턴스 ID는 ULID 문자열**), `CharacterTags`(캐릭터 코드 → 태그 목록), 유닛의 `Equipment`(장비 슬롯 코드 → `{"Kind": "UniqueItem"|"CommonItem"|"Character", "Code": 코드}`; `PartyInstance` 안)로 저장합니다. 유니크 아이템 종류는 `Code` 대신 `Instance`(인스턴스 ID)로 가리킵니다: `{"Kind": "UniqueItem", "Instance": "01H..."}`. **캐릭터와 유니크 아이템 인스턴스는 자기 태그를 가집니다**: 인스턴스를 만들 때(캐릭터는 처음 저장/변경할 때) 각자의 태그 마스터에서 복사하고, 게임 중에 태그가 추가되거나 사라질 수 있으며(예: 변신한 상태에서만 낄 수 있는 아이템), 세이브의 `Tags`/`CharacterTags`가 없으면 마스터에서 복사합니다. 커먼 아이템은 인스턴스가 없어 늘 마스터의 태그입니다. 태그가 바뀌어 끼운 것이 더는 슬롯 규칙에 맞지 않으면 장비에서 빠집니다. 커먼 아이템의 보유는 인벤토리 수량, 캐릭터의 보유는 보유 캐릭터입니다. 한 개는 한 곳에만 낄 수 있습니다. 끼워 둔 커먼 아이템은 상점 교환 비용으로 쓸 수 없고(**파티에 편성된 캐릭터도** 어느 파티든 코스트로 낼 수 없으며 교환 항목이 회색이 됩니다), 캐릭터는 자기 자신을 낄 수 없습니다. 장비 선택 화면은 열 때마다 `OrderNumber`순(같으면 인스턴스 ID순)으로 다시 정렬하며, 유니크 아이템의 항목 번호가 `OrderNumber` 그대로입니다(입력 코드도 같음; 해제가 0번을 쓰고 있으면 1부터이고, 같은 번호가 이미 쓰였으면 다음 빈 번호). `OrderNumber`가 없는 커먼 아이템과 캐릭터는 그 뒤로 이어서 번호를 붙입니다.
  - 낄 수 있으려면 ① 캐릭터가 보유 캐릭터이고 ② 장비가 그 슬롯의 태그 조건에 부합하며 ③ 남는 개수가 있어야 합니다. 슬롯에 다른 장비가 있으면 새 장비로 교체되고 빠진 장비는 보유로 돌아갑니다. 파티에서 빠져도 장착은 유지됩니다.
  - 장비 슬롯 목록(`용사의 장비`)은 `무기 : 철검`처럼 낀 장비를 보여 주고, 슬롯을 고르면 그 슬롯에 **지금 낄 수 있는 보유 장비**가 클릭 가능한 항목으로 나옵니다(지금 끼고 있는 것은 `(장착중)`). 항목을 고르면 장착하고 같은 캐릭터의 장비 슬롯 목록으로 돌아가며 결과 메시지가 나옵니다. 장비를 낀 슬롯에서는 맨 위에 **`[0] 해제`**가 나오고, 이때 장비 번호는 1부터 시작합니다(해제가 없으면 0부터). 다른 곳에 끼어 남는 개수가 없는 장비는 목록에 나오지 않습니다.
  - 세이브를 불러올 때 검증합니다: 보유 장비와 장착 장비는 장비 마스터에 있어야 하고, 장착한 캐릭터는 보유 캐릭터, 슬롯은 그 캐릭터의 장비 슬롯, 장비는 그 슬롯 태그에 부합해야 하며, 장비마다 낀 개수가 보유 개수를 넘으면 안 됩니다.
- **속성 전투 규칙**(전투 시스템이 생기면 적용, 아직 코드에는 없음): 유리속성으로 공격하면 데미지와 명중률이 ×1.5, 불리속성으로 공격하면 ×0.5입니다. 피격 쪽은 공격 속성이 자신의 유리속성이면 ×0.5, 불리속성이면 ×1.5입니다. 두 보정은 곱하므로 유리속성 공격자가 불리속성 피격자를 치면 ×2.25입니다.
- **교환**(`shop_trade_master`)은 상점 `shop_code`에서 `cost_item_code`를 `cost_amount`개 내고 `receive_item_code`를 `receive_amount`개 받는 것입니다. 아이템 코드는 아이템/번치 인벤토리 어느 쪽이든 가능하고, 어마운트는 1 이상입니다. 상점과 아이템 코드는 해당 마스터에 있어야 합니다.
  - **종류 열**: 여섯 열 뒤에 `cost_kind`, `receive_kind`를 **둘 다** 붙일 수 있습니다(순서 고정). 값은 `common_item`(커먼/번치 아이템), `unique_item`(유니크 아이템), `character`(캐릭터)입니다. 인벤토리 코드는 하나의 코드 공간이라 **비워 두면 코드가 속한 인벤토리 마스터로 종류를 알아내고**(번치는 커먼 아이템), 적었다면 그 코드의 마스터와 같아야 합니다(다르면 로드 오류). 여섯 열만 있는 교환도 같은 방식으로 종류가 정해집니다.
  - **유니크 아이템과 캐릭터는 코스트로도 리시브로도 어마운트가 1**이어야 합니다(아니면 로드 오류). **유니크 아이템을 받으면** 새 인스턴스(ULID)가 만들어지고(마스터 태그 복사), **내면** 장비 슬롯에 끼지 않은 인스턴스가 ID가 작은(먼저 얻은) 것부터 쓰입니다.
  - **캐릭터를 받으면** 레벨 0 스테이터스로 새 캐릭터가 되고(이미 보유하면 교환 실패), **내면** 보유에서 빠지며 파티 슬롯, 상태이상, 태그가 지워지고 끼고 있던 장비는 보유로 돌아갑니다(다른 캐릭터의 장비 슬롯에 끼워져 있으면 낼 수 없음).
  - 어느 쪽이든 모자라거나 불가하면 아무것도 바꾸지 않고 사유를 알립니다.
- **교환 조건표**(`shop_trade_condition_master`)는 던전/상점 조건표와 같은 규칙(그룹 AND/OR, `None`)이고, 조건이 없으면 항상 가능합니다.

### 던전 마스터
`master/dungeon_master_v1.tsv`가 있으면 던전 마스터로 읽습니다. 새 게임과 불러오기는 (튜토리얼이 구현될 때까지) 항상 홈 화면으로 들어갑니다. 세이브에 저장된 화면은 무시합니다.

- 던전 입장 조건은 `dungeon_flag_master_v1.tsv`에 적습니다. 같은 던전의 **같은 그룹은 AND, 그룹끼리는 OR**입니다. 조건이 없는 던전은 항상 입장할 수 있습니다.
- `condition_type`: `None`(조건 없음, 플래그 코드/밸류 생략 가능), `Equal`, `NotEqual`, `GreaterThan`, `GreaterOrEqual`, `LessThan`, `LessOrEqual` (대소문자 무시). 값이 없는 플래그는 0이고, `condition_value`는 `long` 범위의 정수입니다.
- 홈 화면의 `[101] 던전`은 입장 가능한 던전이 하나 이상일 때만 나타납니다. 클릭하거나 `101`을 입력하면 던전 선택 화면으로 갑니다(던전 입장은 아직 구현 전이라 이 화면에는 던전 목록과 `[999] 돌아가기`만 있습니다). 화면의 클릭 가능한 텍스트는 모두 `[코드]`를 입력해도 동작합니다(`[999] 돌아가기`). **`[999] 돌아가기`는 모든 화면에서 같은 자리, 즉 코드 입력줄 바로 위 오른쪽 끝에 따로 표시됩니다**(돌아갈 곳이 있는 화면에만 나오고 화면 안의 목록에는 들어가지 않습니다).
- 상점도 같은 방식입니다. 조건표(`shop_condition_master_v1.tsv`)의 그룹 규칙과 `condition_type`은 던전과 같고, 홈의 `[102] 상점`은 열려 있는 상점이 하나 이상일 때만 나타납니다.
- 상점 화면에는 열린 상점이 `[상점코드] 이름`으로 나오고, 클릭하거나 코드를 입력하면 그 상점의 **교환 목록**이 나옵니다. 목록에는 조건을 만족한 교환만 `[교환코드] 코스트 ×수량 → 받을것 ×수량` 형태로 보입니다(아이템은 이름으로). 교환 목록의 `[999]`는 상점가로, 상점가의 `[999]`는 홈으로 돌아갑니다. 교환 항목을 클릭하거나 교환 코드를 입력하면 교환이 **실행**됩니다. **지금 할 수 있는 교환은 흰색, 할 수 없는 교환(코스트 부족, 소지제한 초과, 이미 가진 캐릭터를 받음 등)은 회색**으로 보이고 회색 항목은 누르거나 코드를 입력해도 아무 반응이 없습니다(메시지도 없음). `[999] 돌아가기`는 늘 흰색입니다(상점 목록 화면의 글자도 흰색). 코드에서는 `GameSession.CanTrade(교환 코드)`와 못 하는 까닭을 알려 주는 `TradeBlockedReason`, 항목의 `ScreenEntry.Enabled`로 확인합니다.
  - 코스트 아이템이 인벤토리에서 줄고 리시브 아이템이 늘어납니다. 0개가 되면 인벤토리에서 지워집니다.
  - 코스트가 모자라거나 받은 뒤 수량이 아이템의 소지제한(`carry_limit`)을 넘으면 아무것도 바꾸지 않고 사유를 보여 줍니다(번치를 받을 때는 풀린 부품 각각에 적용). 조건을 만족하지 못한 교환은 코드를 입력해도 실행되지 않습니다.
  - 번치 아이템은 부품으로 풀어서 처리합니다. 받으면 `부품 × part_amount × 개수`가 인벤토리에 들어가고(번치 코드 자체는 들어가지 않음), 내려면 같은 만큼의 부품이 필요합니다.
  - 코스트는 받기 전의 보유량으로 판단합니다(같은 아이템이 양쪽에 있어도 마찬가지).
- 플래그 값은 화면에 표시하지 않으며, 인벤토리 확인 화면은 나중에 추가됩니다.
- 이 게임은 검은 바탕에 흰 글자, **등폭 폰트**를 씁니다.

### 전투(임시) 작전 화면 (`[110]`)
- 지금 보는 파티로 전투 마스터 `5001`(`GameSession.TemporaryBattleCode`)을 시작합니다. 적은 전투 적 마스터(`battle_enemy_master`)의 프리셋 파티 중 **가중치(`weight`)로 하나를 뽑고**(`GameSession.NextRandom`), 적 슬롯의 레벨, HP, XP는 프리셋 유닛 캐릭터의 캐릭터 스테이터스 마스터 레벨 0 값입니다(장비와 드롭은 아직 쓰이지 않음). 전투 마스터나 적 파티가 없으면 시작하지 못했다는 안내만 나옵니다.
- 화면은 위에서부터 **적 후위, 적 중위, 적 전위, 가운데 영역(경계선), 아군 전위, 아군 중위, 아군 후위**의 일곱 줄 중 다섯 줄(슬롯 네 줄과 가운데 영역)을 한 번에 보여 주며, 보는 구성은 **두 가지뿐**입니다: **적 3 / 아군 1**(`적 후위 / 적 중위 / 적 전위 / 가운데 영역 / 아군 전위`)과 **적 1 / 아군 3**(`적 전위 / 가운데 영역 / 아군 전위 / 아군 중위 / 아군 후위`). 구분선 아래 오른쪽의 `[1000] ▲`는 바로 적 3 / 아군 1로, `[1001] ▼`는 바로 적 1 / 아군 3으로 갑니다(가운데 구성은 건너뜀; 지금 그 구성이면 해당 버튼이 회색). 슬롯 줄에는 줄 이름(`전위`, `중위`, `후위`)과 슬롯 셋이 나옵니다.
- **보는 캐릭터**: 아군 파티의 유닛 중 지금 행동을 설정하는 캐릭터입니다(칸 순서). 이름(슬롯 이름 줄)이 **파란색**으로 보이고, 리더는 평소에는 연두색이지만 보는 캐릭터일 때는 파란색입니다. **턴이 시작될 때(전투를 시작할 때 포함) 첫 유닛이 보는 캐릭터가 되고, 설정해 둔 행동이 모두 지워지며, `[101] 다음 캐릭터`/`[104] 이전 캐릭터`로 다른 캐릭터로 옮길 때도(끝에서 처음으로 이어짐) 화면이 적 1 / 아군 3으로 강제로 바뀝니다.** 그 뒤의 `[1000]`, `[1001]` 화면 전환은 기본 커맨드에서도 행동 후보에서도 자유입니다.
- **커맨드**(구분선 아래, 두 줄): 윗줄 `[101] 다음 캐릭터`, `[102] 행동 설정`, `[103] 상태 확인`과 그 줄의 오른쪽 끝 `[1000] ▲`, `[1001] ▼`, 아랫줄 `[104] 이전 캐릭터`, `[105] 아이템`, `[106] 실행`. `[102] 행동 설정`을 누르면 커맨드가 **보는 캐릭터의 행동 후보**(`[101]`~`[104]` 스킬1~4; 사용 가능한 스킬 목록은 나중에 쓰고 지금은 고정)와 `[106] 취소`로 바뀌고 화면은 적 3 / 아군 1로 바뀝니다. 스킬을 고르면 그 캐릭터의 이번 턴 행동이 정해지고 기본 커맨드로 돌아옵니다. **`[106] 실행`은 파티의 모든 유닛이 행동을 설정해야 누를 수 있고(아니면 회색) 아직 동작은 없습니다.** `[103] 상태 확인`과 `[105] 아이템`도 아직 동작이 없습니다.
- **가운데 영역**(경계선)은 왼쪽에 적 파티 이름(프리셋 파티 마스터의 `name`), 가운데에 전투 이름, 오른쪽에 아군 파티 이름(보는 파티의 이름)을 한 줄에 보여 줍니다. 세 칸은 높이의 가운데에서 넓이가 **1/3씩**이고 가로선에서 **30도** 기운 사선 둘로 나뉩니다(가운데 칸은 위아래 선이 있는 평행사변형). 왼쪽 칸은 아래쪽 선만, 오른쪽 칸은 위쪽 선만 이어져서 적 파티명은 위의 적 파티에, 아군 파티명은 아래의 아군 파티에 속해 보입니다.
- 전투 중에는 `[999] 돌아가기`가 없습니다(전투에서 빠져나가는 수단은 아직 없음). 행동을 설정한 유닛은 슬롯 이름 자리에 **행동 이름**(스킬1~4)이 표시됩니다(아이콘이 캐릭터를 나타냄). 전투 진행은 아직 없습니다.

### 파티 설정 (`[105]`, 홈에 조건 없이 항상 나옴)
- 슬롯 아래에 **파티 선택 버튼**(`[11] 파티-A` ~ `[26] 파티-P`, 한 줄에 4개씩)과 모드를 바꾸는 텍스트 버튼이 있습니다: **`[101] 캐릭터 배치`**, **`[102] 장비 착용`**, **`[103] 리더 지정`**(클릭하거나 코드 입력). 슬롯과 파티 버튼 사이, 파티 버튼과 모드 버튼 사이에는 구분선이 있고, 모드 버튼은 4분할 위치에 가로로 놓이며 `[999] 돌아가기`는 다음 줄에 있습니다. 지금 보고 있는 모드의 버튼은 파란색이고 눌리지 않으며(`Enabled=false`), 고를 수 있는 다른 모드는 흰색입니다. 두 화면의 제목은 모두 `파티 설정 : [0] 파티명`이고, **`[0]`을 누르거나 `0`을 입력하면 파티 이름을 바꾸는 화면**(`파티 설정 : 이름 변경`)으로 갑니다. 거기서 입력칸에 새 이름을 쓰고 Enter를 누르면(앞뒤 공백은 없애며, 비어 있거나 20자를 넘으면 바뀌지 않음; 숫자도 이름이 됨) 보고 있는 파티의 이름이 바뀌고 들어온 화면(캐릭터 배치 또는 장비 착용)으로 돌아갑니다. `[999] 돌아가기`는 이름을 바꾸지 않고 돌아갑니다.
  - **파티 16개**: 플레이어는 파티를 열여섯 개(처음 이름은 `파티-A` ~ `파티-P`; 다른 전투에 파견하기 위함) 가지며 새 게임은 `파티-A`를 보고 있습니다. 파티 버튼을 누르면(같은 화면에 머묾) 그 파티를 보고, 슬롯과 캐릭터 배치, 장비 착용은 보고 있는 파티를 따릅니다. 보고 있는 파티의 버튼은 파란색이고 눌리지 않습니다. **파티끼리는 캐릭터도 장비도 공유할 수 없습니다**: 다른 파티에 있는 캐릭터는 배치 목록에서 회색이라 고를 수 없고, 아이템 한 개는 한 파티의 한 유닛에만 낄 수 있습니다. 세이브는 `Parties`(파티 배열)와 `CurrentParty`(보고 있는 파티 번호)에 저장하고, 예전 세이브(`PartyInstance` 하나나 `Party`)는 파티-A로 읽습니다.
  - **리더**: 리더 태그(태그 마스터의 예약 코드 2, 반드시 있어야 함)를 가진 캐릭터만 리더가 될 수 있고, **파티에는 리더가 한 명 이상 있어야 합니다**. 리더로 지정된 유닛의 슬롯명(`Lv.XX`와 `[번호] 이름`)은 연두색입니다. **리더 지정** 화면(돌아가기는 홈)에서는 리더 태그를 가진 캐릭터의 슬롯만 고를 수 있고, 고르면 리더로 지정하거나(이미 리더면) 해제합니다. 마지막 리더는 해제할 수 없습니다(안내 문구가 나옴). **파티에 아무도 없을 때와 리더의 슬롯의 캐릭터를 바꿀 때는 배치 목록에 리더 태그를 가진 캐릭터만 나오고**(다른 캐릭터는 걸러짐), 아무도 없던 파티에 처음 둔 유닛이나 리더 슬롯을 이은 유닛은 리더가 됩니다. 다른 동료가 남아 있는 마지막 리더의 슬롯은 `[0] 비우기`가 나오지 않습니다(혼자일 때는 비울 수 있음). 어떤 이유로 리더가 없어진 파티(리더가 리더 태그를 잃거나 파티에서 빠짐)는 다른 유닛이 대신 리더가 되지 않고 **던전(전투)에 파견할 수 없습니다**(`GameSession.IsDispatchable`); `[103] 리더 지정`에서 다시 지정합니다. 세이브는 유닛의 `IsLeader`에 저장하고, 리더 정보가 없던 예전 세이브의 파티는 리더 없는 파티로 읽습니다.
  - **캐릭터 배치**: 아래에 나오는 방식으로 슬롯의 캐릭터를 배치합니다. 돌아가기는 홈입니다.
  - **장비 착용**: 같은 3×3 슬롯이 나오지만 캐릭터가 있는 슬롯만 고를 수 있습니다(빈 슬롯은 눌러지지 않음). 슬롯을 고르면 그 캐릭터의 **장비 슬롯 목록**(`○○의 장비`)으로 갑니다. 거기서 슬롯(`[슬롯코드] 무기` 등)을 고르면 그 슬롯에 낄 수 있는 **장비 가능 목록**(`○○의 무기`)이 나옵니다. 이 화면(장비 착용)에서 돌아가기를 하면 **파티 설정이 아니라 홈**으로 갑니다. 장비 슬롯 목록에서 돌아가면 장비 착용 화면, 장비 가능 목록에서 돌아가면 같은 캐릭터의 장비 슬롯 목록입니다.
- 3×3 슬롯입니다. 위 줄이 전위(슬롯 1~3), 가운데 줄이 중위(4~6), 아래 줄이 후위(7~9)입니다. 각 줄의 슬롯 위에 줄 이름(`전위`, `중위`, `후위`)이 구분선과 함께 한 줄로 나옵니다.
- 슬롯은 왼쪽에 캐릭터 아이콘, 오른쪽에 4줄을 보여 줍니다(첫 줄은 왼쪽에 `Lv.XX`, 줄 오른쪽 끝(HP 게이지의 끝과 같은 곳)에 `[슬롯번호] 이름`; 빈 슬롯은 레벨 자리가 비고 `[슬롯번호] 빈 슬롯`; 슬롯 번호 1~9를 입력해도 고를 수 있음). 아이콘은 이 4줄 높이의 정사각형입니다.
  1. `Lv.5` (왼쪽 정렬) … `용사` (오른쪽 정렬)
  2. `HP : ****36/40***-`
  3. `XP : *----3/30----`
  4. 아이콘 줄: `[속성 아이콘 ⭕] [속성 아이콘 ❌]`. ⭕는 캐릭터의 유리속성, ❌는 불리속성입니다. 아이콘은 1줄 높이의 정사각형이고, 마우스를 올리면 속성 이름이 보입니다. 속성 아이콘 둘은 왼쪽 정렬이고, 걸려 있는 상태이상 아이콘은 같은 줄 오른쪽 끝에 정렬됩니다(걸린 순서대로, 마우스를 올리면 상태이상 이름; 걸린 것이 없으면 나오지 않습니다). 이미지는 아직 No Image입니다. 빈 슬롯은 공란입니다.
- 게이지는 13칸이고, 채운 칸은 `*`, 빈 칸은 `-`이며 가운데에 `현재/최대`를 겹쳐 씁니다. 색은 50% 이상 흰색, 25% 이상 노랑, 그 아래 빨강이고 사망한 캐릭터는 회색입니다.
- 비어 있는 슬롯은 `빈 슬롯`, 회색 `0/0`입니다. 아이콘은 `No Image` 기본 이미지이고, 캐릭터 이미지 리소스가 없을 때도 이 이미지를 씁니다(지금은 항상).
- 슬롯의 이름이나 아이콘을 클릭하거나 슬롯 번호(1~9)를 입력하면 그 슬롯에 배치할 **캐릭터 목록**으로 갑니다. 그 슬롯에 이미 있는 캐릭터는 목록에 나오지 않습니다(서포트 슬롯 선택도 같습니다). 흰색은 배치 가능, 회색은 배치 불가(보유하지 않음), 파란색은 이미 다른 슬롯에 배치된 파티원입니다. 장비 착용 모드에서 고를 수 없는 빈 슬롯의 이름은 회색입니다.
  - 흰색을 고르면 그 슬롯에 배치합니다(원래 있던 캐릭터는 파티에서 빠짐).
  - 파란색(다른 슬롯에 배치된 파티원)을 고르면 위치를 서로 바꿉니다. 고른 슬롯이 비어 있으면 그 캐릭터가 이동합니다.
  - 캐릭터 선택 화면 맨 위의 **`[0] 비우기`**(클릭하거나 `0` 입력)를 고르면 그 슬롯의 캐릭터가 파티에서 빠지고 슬롯이 빈 슬롯이 되어 파티 설정으로 돌아갑니다. 캐릭터를 잃는 것은 아니고 여전히 보유 상태입니다. 선택한 슬롯이 비어 있으면 이 항목은 나오지 않습니다.
- 캐릭터 상태(레벨, HP, XP)는 세이브의 `Characters`에, 파티는 `PartyInstance`에 저장합니다.
  - `Characters`: 캐릭터 코드 → **캐릭터 인스턴스** `{ "InstanceId", "CharacterCode", "OrderNumber", "Level", "Hp", "MaxHp", "Xp", "XpMax" }`(구조체 `CharacterInstance`). 코드(키)는 캐릭터 인벤토리 마스터에 있어야 하고, 이 목록이 보유 캐릭터입니다. `InstanceId`는 ULID 문자열, `CharacterCode`는 마스터 코드(키와 같아야 함), `OrderNumber`는 동료 목록의 순서입니다(얻을 때 소지 캐릭터 수이고(0부터 시작), 순서를 바꿀 때 이 값을 조작합니다). 이 세 필드가 없는 예전 세이브는 불러올 때 채웁니다(ID는 캐릭터 코드 순서대로 새로 만들고 코드는 키로 맞춥니다). 같은 `InstanceId`가 두 번 있거나 ULID가 아니면 세이브 오류입니다.
  - `PartyInstance`: 파티 인스턴스 `{Name, Units}`. `Name`은 파티 이름(없으면 `아군 파티`)이고 `Units`는 길이 9의 유닛 배열(슬롯 순서; 칸 0~2 전위, 3~5 중위, 6~8 후위)입니다. 빈 칸은 `null`이고 유닛은 `{CharacterCode, Equipment}`(**유닛 = 캐릭터 + 장비**, **파티 = 유닛들**)입니다. `Equipment`는 장비 슬롯 코드 → 낀 것입니다. 보유한 캐릭터만 배치할 수 있고 같은 캐릭터를 두 번 배치할 수 없습니다. 장비는 유닛에 속하므로 **유닛이 파티에서 빠지면(비우기, 다른 캐릭터로 교체, 캐릭터를 내보냄) 그 유닛의 장비는 해제되어 보유로 돌아가고**, 슬롯끼리 맞바꾸면 장비도 유닛과 함께 이동하며, 같은 캐릭터를 다시 고르면 아무것도 바뀌지 않습니다. 파티에 없는 캐릭터에게는 장비를 끼울 수 없습니다. 예전 세이브의 `Party`(캐릭터 코드 배열)와 `EquippedItems`(캐릭터별 장비)도 읽어서 유닛으로 옮깁니다(파티에 없던 캐릭터의 장비는 보유로 돌아감). 코드에서는 `GameSession.PartyInstance`(`PartyUnit`, `PartyInstance`)이고, 칸 번호로 캐릭터 코드를 읽고 쓰는 `GameSession.Party`(`PartySlots`)도 있습니다.
  - `StatusEffects`: 캐릭터 코드 → 걸려 있는 상태이상 목록(**복구 가능한 값**). 상태이상마다 `StatusEffectCode`와 `Effects`(이펙트 행들)를 저장하고, 이펙트 행은 `Trigger`(이름), `Priority`, `EffectCode`, `Value1~3`, `Counter`, `IsValid`를 모두 가집니다. 걸린 시점의 마스터 값을 복사해 두므로 게임팩의 마스터가 나중에 바뀌어도 걸려 있던 이펙트는 저장한 값으로 복구됩니다.
    - 불러올 때 캐릭터는 보유 캐릭터여야 하고, 상태이상 코드는 상태이상 마스터에, 이펙트 코드는 임베디드 이펙트에 있어야 합니다. 같은 캐릭터에 같은 상태이상을 두 번 걸 수 없고, 트리거 이름이 올바라야 하며 카운터는 0 이상이어야 합니다.
    - 코드에서는 `GameSession.ApplyStatusEffect(캐릭터 코드, 상태이상 코드)`(이미 걸려 있으면 새로 걸어 갱신), `RemoveStatusEffect`, `StatusEffectsOf`로 다룹니다. 저장한 이펙트는 `ActiveEffect.Restore(등록부, 타겟)`로 카운터와 유효 플래그까지 그대로 가진 임베디드 이펙트 인스턴스로 되살리고, `ActiveEffect.Capture(...)`로 실행 중인 이펙트의 현재 값을 다시 저장용으로 뜹니다.
- **동료 확인**(`[201]`): 지금 가진 캐릭터를 당신을 포함해 `[{OrderNumber}] {이름} Lv {레벨} Hp {HP} Xp {XP}` 줄로 나열합니다. 칸은 고정 너비의 왼쪽 맞춤입니다: 코드 칸(`[순서 번호]`)은 반각 8칸, 이름 칸은 반각 32칸(한글은 2칸), `Lv 값`, `Hp 값`, `Xp 값` 칸은 반각 8칸씩이고 모두 왼쪽 맞춤이며 코드와 이름 사이는 공백으로 채웁니다(예: `[0]      당신                             Lv 1     Hp 40    Xp 0`). 순서는 `OrderNumber`순이고 같으면 `InstanceId`순입니다(`GameSession.OwnedCharacters`, `Companions`).
- **장비 확인**(`[202]`): 지금 가진 장비(유니크 아이템)를 `[{OrderNumber}] {장비 이름}`으로 나열합니다(코드 칸 반각 8칸, 이름 칸 반각 32칸, 왼쪽 맞춤; 동료 확인과 같음). 순서는 `OrderNumber`순, 같으면 `InstanceId`순입니다(`GameSession.OwnedUniqueItems`, `Equipments`). 목록의 `[ ]` 안은 항목 코드가 아니라 정렬 순서(`OrderNumber`)라서 순서를 바꾸는 기능이 이 값을 조작합니다(동료 확인도 같음). 예시 게임팩은 테스트용 유니크 아이템 `8007 순례자의 은단검`을 `pack.tsv`의 `debug_start_unique_items`로 새 게임부터 가지고 시작합니다.
- **아이템 확인**(`[203]`): 지금 가진(수량 1 이상) 커먼 아이템을 `[{아이템 코드}] {이름} 수량 {N}`으로 나열합니다(코드 칸 반각 8칸, 이름 칸 32칸, 수량 칸 16칸, 왼쪽 맞춤). 순서는 커먼 아이템 인벤토리 마스터 순서이고, 장비에 끼워 둔 것도 수량에 포함됩니다. 가진 것이 없으면 목록이 비어 있습니다(`GameSession.Items`). 여기 `[ ]` 안은 정렬 순서가 아니라 아이템 코드입니다.
- 홈 화면에는 `[200] 세이브`(현재 상태를 `.wsv`로 내려받기)와 `[300] 로드`(로드 화면에서 `.wsv`를 드롭)도 항상 있습니다. 로드 화면과 던전 선택 화면의 돌아가기는 `[999]`입니다.
- **교류 흐름 찾기**: 교류의 흐름은 **듀오 → 솔로 → 기본** 순으로 찾아 흐름이 있는 첫 마스터의 칸들을 한 묶음으로 씁니다(칸 하나씩이 아니라 묶음 단위로 폴백합니다). 듀오는 (교류, 파트너 캐릭터, 어시스트 캐릭터), 솔로는 (교류, 파트너 캐릭터), 기본은 교류 코드로 찾습니다. 교류의 `is_assist`가 true면 솔로는 파트너 대신 **어시스트 캐릭터**로 찾고, 듀오는 파트너와 어시스트 자리를 뒤바꿔(`partner_code`에 어시스트 캐릭터, `assist_code`에 파트너 캐릭터) 찾습니다. 필요한 슬롯이 비어 있으면 그 단계는 건너뜁니다(`GameSession.CommunicationFlowOf`, `GamePack.FindCommunicationFlow`).

- **홈 메뉴**는 날짜 표시 아래에 구분선으로 나뉜 세 분류입니다. **[RPG]**: `[101] 던전`과 `[102] 상점`(입장할 수 있는 것이 없으면 메뉴에서 빼지 않고 **회색으로 두며 눌러도 반응이 없습니다**), `[103] 이벤트`, `[104] 교류`, `[105] 파티 설정`, `[110] 전투(임시)`(**리더가 없는 파티는 던전에 파견할 수 없어서**, 지금 보고 있는 파티에 리더가 없으면 회색이고 눌러도 반응이 없습니다; 누르면 전투 마스터 `5001`(예시 게임팩의 `테스트 전투`)을 고정으로 시작해 작전 화면으로 갑니다. 아래 "전투(임시) 작전 화면" 참고). **[정보]**: `[201] 동료 확인`, `[202] 장비 확인`, `[203] 아이템 확인`. **[시스템]**: `[200] 세이브`, `[300] 로드`. 선택할 수 있는 메뉴는 흰색, 선택할 수 없는 메뉴는 회색입니다. 각 분류의 항목은 **한 줄에 최대 4개씩**, 구분선의 너비를 4등분한 칸에 가로 전체로 펼쳐 늘어서고(101~104가 한 줄, 105와 110이 다음 줄) 
- **이벤트 실행**(`GameSession.StartEvent(이벤트 코드)` → `EventFlowCircuit.Advance()`): 이벤트 마스터에 있고 이벤트 조건을 만족하면 시작합니다. 흐름은 `flow_number` 순서로 진행하며 칸에는 조건이 없습니다(조건에 따라 건너뛰려면 `JumpFlag*`로 뛰어넘습니다). 이벤트는 **(1) 더 진행할 `flow_number`가 없거나 (2) `Finish` 칸을 만나면** 끝납니다. `None`은 아무 일도 하지 않고, `Jump`는 `param_1` 번호부터 이어 가고, `JumpFlag*`는 플래그를 견주어 참이면 `param_3` 번호부터 이어 가고 거짓이면 다음 칸으로 가며, `Adv`/`Battle`은 `Advance()`가 `EventStep`(종류, 흐름 번호, adv/battle 코드)으로 돌려주고 멈춥니다. **[103] 이벤트 화면**에는 조건을 만족하는 이벤트가 `[코드] 이름`으로 나열되고, 고르면 시작해 장면마다 `ADV: 이름` / `전투: 이름`을 보여 주며 `[1] 다음`으로 이어 갑니다(ADV 재생과 전투 자체는 아직 없어 장면 이름만 보입니다). ADV 장면은 `AdvFlowCircuit`이 이벤트와 같은 규칙(`Finish`나 칸이 없으면 끝, `Jump`, `JumpFlag*`)으로 진행합니다. `TextMe`는 **왼쪽에 파티 슬롯과 같은 크기의 이미지, 오른쪽에 왼쪽 위 테두리에 `[ 이름 ]`(`param_1` 캐릭터의 이름)이 걸린 텍스트 상자**로 나오고, `TextYou`는 그 좌우 반전(왼쪽에 이름이 걸린 텍스트 상자, 오른쪽에 이미지), `TextPlain`은 상자 없는 일반 텍스트로 나오며 아무 키나 누르거나(키를 누르고 있어 반복되는 입력과 Shift/Ctrl/Alt/Meta/Tab/Esc는 제외) 장면을 누르면 다음으로 넘어갑니다(`[1] 다음` 같은 항목은 보여 주지 않지만 코드 `1`을 입력해도 같습니다). `Choice`는 같은 그룹의 이어진 선택지 중 조건을 만족하는 것이 `[1]`, `[2]`… 로 나열되고(만족하는 것이 없으면 건너뜀) 고르면 그 선택지의 `param_2` 번호부터 이어 갑니다. **게임 화면은 960×900 고정**(밖은 회색이고 게임 화면은 페이지 맨 위에 붙어 위쪽에는 회색 여백이 없음; 게임팩 고르기와 세이브 고르기 화면도 같은 크기이고 그 화면들의 끌어다 놓는 영역은 남는 높이를 모두 채우고 맨 아래 줄에는 버튼이 있음)이고, 위쪽 화면 영역은 넘치면 스크롤되며 **코드 입력칸은 홈 이후 모든 화면의 맨 아래에 좌우 폭 끝까지 늘 보입니다.** 같은 ADV의 대사 상자는 지우지 않고 아래로 이어 붙고(새 ADV가 시작되면 비워짐) 새 장면이 나올 때마다 맨 아래(최신 대사)로 스크롤되며, 위로 올리면 지난 대사를 볼 수 있습니다(입력칸에 글자를 쳐도 스크롤은 유지). 선택지 장면에서는 대사들 아래에 선택지 목록이 나옵니다. 선택지를 고르면 고른 선택지(`▶ 문구`, 왼쪽 정렬)가 대사 로그에 남고 고르지 않은 선택지는 사라집니다. 기본 글자색은 **최신 항목이 흰색, 이전 항목은 회색**이고(선택지 목록이 떠 있는 동안에는 목록이 최신이라 로그는 모두 회색), 선택지 목록은 흰색입니다(`[color=…]`로 정한 색은 그대로). 선택지 문구에도 꾸밈 문법(`[b]`, `[color]`)을 쓸 수 있고 줄바꿈(`\n`)은 쓸 수 없습니다(로드 오류). 키/클릭으로 넘기는 장면에서는 비어 있는 입력칸의 Enter도 다음으로 넘깁니다. ADV가 끝나면 이벤트의 다음 칸으로 넘어가고, 흐름이 하나도 없는 ADV는 바로 넘어갑니다. 이벤트가 끝나면 이벤트 화면으로 돌아옵니다. 진행 중인 이벤트는 세이브되지 않습니다.

- `src/Wera.Web` — Blazor WASM UI
- 마스터 데이터는 [MasterMemory](https://github.com/Cysharp/MasterMemory)(인메모리 읽기 전용 DB)에 올립니다. 테이블 정의는 `src/Wera.Core/Masters/MasterRows.cs`, 조회는 `GamePack.Masters.cs`(`GamePack.Masters`, `FindCharacter` 등)입니다. TSV 파싱과 외래키 검증은 기존 로더가 하고, 결과를 테이블로 올린 뒤 `Validate()`로 기본키 중복을 한 번 더 확인합니다. 테이블은 행 순서(int 순번)를 따로 기억하지 않고 기본키 순서로 저장되며, 순서가 필요한 조회(번치 부품, 상태이상 이펙트, 슬롯 규칙, 태그 등)는 키 순서대로 `OrderBy`/`ThenBy` 합니다. 화면에 나오는 목록(던전, 상점, 캐릭터 등)은 게임팩 파일 순서 그대로입니다. 복합키가 같은 행은 두 번 쓸 수 없고(오류), 던전/상점/교환 조건표는 `(코드, group_number, flag_code)`, 상태이상 이펙트는 `(status_effect_code, trigger_type, effect_code)`가 복합키입니다.
- `tests/Wera.Core.Tests` — xUnit 테스트

## 개발
```
dotnet test tests/Wera.Core.Tests
dotnet run --project src/Wera.Web
```
`main`에 푸시하면 GitHub Actions가 Pages로 배포합니다 (저장소 설정 → Pages → Source: GitHub Actions).
